# 画面の崩れの点検（UI 監査）

スクロール時の崩れ・レイアウトの崩れ・文字の潰れを、Playwright で 320〜1280px・ライト/ダーク・横向き（740×360）・文字を大きくした状態で撮って洗い出し、直したものと残っているものをまとめる。

## 直したもの（ループ 1・2）

- 長いメモ・著者名・線の名前・URL の例が画面の外へはみ出す（ページが横にスクロールする）
- スマホでシートが画面の端まで届かない・開いている間も後ろがスクロールする・横向きで保存ボタンが見えない
- 紙の本の登録・本の情報・読書記録のシートで、保存できなかった理由がトーストに出てシートの下に隠れる
- 分析中に「本棚」が 1 文字ずつ折れて上のバーが伸び、貼りつく検索欄がその下に潜る
- トーストが画面幅の半分で折り返す・デスクトップで画面いっぱいに広がる
- 文字を大きくするとタブの名前が 2 行になって切れる・本文が端末の文字の大きさに従わない
- 「読んだ本」「ページ」「・ n 点」「＋n」「遠い組」などが途中で折れる・1 文字だけ次の行に残る
- 長い書名の見出しで句読点が行頭に来る
- ファイル・日付・数値の入力欄だけ見た目がそろっていない
- 分析の段階（6 つ）が 5 列の枠で 2 行になる
- 知識マップの文字がスマホで 6px 台になる・拡大縮小が効かず中心がずれる・面の名前が重なる
- 読書記録の大きな合計で画面が横にはみ出す
- 「面」の小さな文字・興味なしにした本のコントラスト不足
- ノッチの左右・iPad の下端（safe-area）を避けていない

## 残っているもの

ループ 3 は利用上限で途中で止まったため、次の観点はまだ点検していない。

1. **スクロールと描き直し**: ★・メモの編集・同期の完了・絞り込みのチップを押したあとにスクロール位置が飛ばないか、貼りつく検索欄で入力中にフォーカスが外れないか、戻る操作で位置が戻るか
2. **状態ごとの表示**: データが空のとき（全画面）、長い英語のエラー文（`.notice.err`）、分析中の長い状況の文と進み具合、スクロール中に出るトースト
3. **フォーカスの枠**: `overflow: hidden` の中（`.map-wrap`・`.book-item` など）でキーボード操作の枠が切れないか
4. **文字の潰れ**: `-webkit-line-clamp` で 3 行目の上端が少し見えないか、スマホで 11px 未満になる文字、全画面のコントラスト（4.5:1 未満）の洗い出し
5. **拡張機能の設定画面**（`extension/options.html`）とブックマークレット（`web/bookmarklet/kindle-notebook.js`）が出す画面の崩れ
6. **main に入った新しい画面**: 点の画面（`web/js/views/point.js`）・意味で探す／問いかける（G8）・文章の骨組み（G9）は、ループ 1・2 のあとに入ったので個別には点検していない（320/375 で横のはみ出しが無いことだけ確かめた）
7. **iOS 実機での確認**: safe-area・`100dvh`・シートとソフトキーボードの重なりはヘッドレスの Chromium では再現できない
